# Kids Ad-Free YouTube Player — סרטונים לילדים

PWA סטטית בעברית וב־RTL. ההורה מוסיף רק קישורים לרשימה פשוטה; האפליקציה מזהה סרטון או ערוץ ומביאה את השמות אוטומטית. הניגון מתבצע ב־Invidious והאירוח מיועד ל־GitHub Pages. אין backend, מסד נתונים, API keys, ספריות צד שלישי או build step.

## מבנה

```text
kids-youtube/
├── index.html
├── manifest.json
├── sw.js
├── videos.txt
├── icons/
│   ├── icon-192.png

└── .github/workflows/

```

ששת קובצי האפליקציה הראשונים מספיקים להפעלה. README וקובץ הבדיקות נועדו לתחזוקה בלבד. ה־workflow בודק את הקוד ומפרסם את הקבצים הסטטיים בלי build או התקנת dependencies.

## התחלה ו־GitHub Pages

1. ה־repository הציבורי של הפרויקט הוא `yt2178/kids-youtube`.
2. העלו את **תוכן** תיקיית `kids-youtube` לשורש ה־repository. `index.html` צריך להיות בשורש, ולא בתוך תיקיית `kids-youtube` נוספת.
3. עברו אל **Settings → Pages → Build and deployment**.
4. בחרו **GitHub Actions** בשדה **Source**. הפעולה הזאת נדרשת פעם אחת; לאחר מכן commits ל־`main` מפעילים פריסה אוטומטית. אם הריצה הראשונה נכשלה לפני ההפעלה, עברו ל־Actions והריצו מחדש את **Check and deploy static PWA**.
5. לאחר ש־GitHub מסיים את הפריסה, האתר יהיה בכתובת `https://USERNAME.github.io/kids-youtube/`.
6. פתחו את `videos.txt`, לחצו על העיפרון, הדביקו קישורים שאתם מאשרים ושמרו באמצעות Commit changes.

כל נתיבי האפליקציה יחסיים. אפשר לשנות שם repository או להשתמש בדומיין אחר בלי לשנות נתיבים ב־JavaScript או במניפסט.

ה־repository נוצר על ידי המשתמש. אפשר להעלות את הקוד דרך חיבור GitHub שבצ׳אט לאחר שה־repository נכלל בהרשאות החיבור. אם מופיעה שגיאת `Resource not accessible by integration`, הוסיפו את `kids-youtube` תחת Only select repositories בהגדרות התקנת החיבור ושמרו. החיבור אינו חושף שינוי של הגדרות Pages; יש לבחור GitHub Actions בהגדרות כפי שמתואר לעיל. לא נדרשים סודות או API keys לפריסה.

## הוספה פשוטה: רק קישורים והערות

1. פתחו סרטון או ערוץ ב־YouTube בטלפון → **שיתוף → העתקת קישור**.
2. פתחו [את videos.txt לעריכה](https://github.com/yt2178/kids-youtube/edit/main/videos.txt), והדביקו קישור בשורה חדשה.
3. לחצו **Commit changes**. לאחר שהפריסה ב־Actions מסתיימת, רעננו את אפליקציית הילדים.
4. בדקו את התמונה, שם הסרטון ושם הערוץ שהופיעו. אפשר לפתוח את הסרטון לבדיקה ולחזור עם ״← חזרה״.

אין צורך לכתוב מזהה, שם, פסיקים, מירכאות או סוגריים. סרטונים וערוצים נמצאים באותה רשימה:

```text
// הערות לעצמי
https://youtu.be/VIDEO_ID_HERE // סרטון שאישרתי
https://www.youtube.com/@CHANNEL_HANDLE_HERE // כל הסרטונים של הערוץ
https://www.youtube.com/watch?v=ANOTHER_VIDEO_ID
```

אלה מצייני מקום: החליפו אותם בקישורים האמיתיים שלכם. בקובץ המצורף כל הדוגמאות הן הערות, ולכן שום תוכן אמיתי לא אושר מראש.

`//` בתחילת שורה הופך את כל השורה להערה. אפשר גם להוסיף **רווח ואז `//`** אחרי קישור. `https://` נשמר כחלק מהקישור. שורות ריקות והערות אינן מאשרות תוכן. להסרת אישור מחקו את השורה או הוסיפו `//` לפניה. קובץ ריק או קובץ שכולו הערות מנקה את האישורים. ההערות נשארות בקובץ הציבורי ב־GitHub ולא מוצגות לילדים.

נתמכים קישורי סרטון רגילים, `youtu.be`, `shorts`, `live` ו־`embed`; וקישורי ערוץ מסוג `/channel/UC…`, `/@handle`, `/c/name` ו־`/user/name`, גם עם לשונית כגון `/videos`. קישורי playlists ואתרים אחרים אינם מאשרים תוכן. קישורי שיתוף עם פרמטרים מנורמלים והכפילויות מוסרות לפי מזהה סרטון. אין שדה קלט לקישורים במסך הילדים.

שם סרטון ושם היוצר נמשכים מ־`/api/v1/videos/{id}`. קישור ערוץ עם כינוי מזוהה באמצעות `/api/v1/resolveurl`, ושמו נמשך מ־`/api/v1/channels/{id}`. כשל במופע מעביר למופע הבא. כשל בקישור אחד אינו עוצר את האחרים. שמות שנטענו נשמרים במכשיר. בעת תקלה, קישור ישיר עם מזהה תקין יכול להופיע כ״סרטון מאושר״ עד ששמו ייטען; קישור ערוץ עם כינוי שלא זוהה מעולם ימתין לזיהוי מוצלח.

אישור ערוץ מאשר אוטומטית גם סרטונים עתידיים שלו. סרטונים חדשים ייאספו בכל פתיחה או רענון, וגם בחזרה לאפליקציה אחרי לפחות חמש דקות. אין עבודה ברקע כשהאפליקציה סגורה. הנתיב `/api/v1/channels/{id}/videos` מציג את לשונית הסרטונים הרגילים; Shorts ושידורים חיים של ערוץ אינם נמשכים באמצעות הנתיב הזה. אפשר לאשר סרטון Shorts או live בנפרד על ידי הקישור שלו.

הרשימה הפשוטה אינה דורשת `maxVideos`. ערוצים נטענים בעימוד עד סיום הרשימה או מגבלות ההגנה שלמטה. לפורמט JSON הישן יש תמיכה לצורכי תאימות בתוך `videos.txt`, כולל `maxVideos`, אך אין צורך להשתמש בו.

## הגדרות המופעים והטעינה

בראש סקריפט האפליקציה ב־`index.html` נמצא `INVIDIOUS_INSTANCES`. עדכנו כתובות רק שם. המופעים הראשוניים נבחרו מהרשימה הרשמית של Invidious ב־5 באוקטובר 2026:

https://docs.invidious.io/instances/

בקשת API תקינה משמשת לבדיקת המופע. בכל כשל, JSON לא תקין, חסימת CORS או timeout, מנסים את הבא. המופע שהחזיר תשובה תקינה מקבל קדימות בהמשך. כשל של ערוץ מסוים אינו פוסל את המופע עבור ערוצים אחרים.

אפשר לשנות את `SETTINGS` באותו סקריפט:

| הגדרה | ברירת מחדל |
| --- | --- |
| זמן מרבי לבקשה | 8 שניות, כולל קריאת התשובה |
| תקציב זמן לערוץ | 120 שניות |
| עמודים מרביים לערוץ | 100 |
| סרטונים ללא maxVideos מפורש | 5,000 לערוץ |
| ערוצים שנטענים במקביל | 3 |
| כרטיסים מוצגים בכל מנה | 60, עם כפתור ״עוד סרטונים״ |

בדיקת continuation שחוזר על עצמו עוצרת לולאה אינסופית. אם העמוד הראשון הצליח והבא נכשל, הסרטונים שהתקבלו נשארים ברשימה. הודעות למשתמש נשארות פשוטות ובעברית.

## עדכונים ושמירה במכשיר

`videos.txt` נמשך עם `cache: 'no-store'`; ה־Service Worker **אינו שומר או מיירט** אותו. ייתכן שפריסת GitHub/CDN עדיין לא הסתיימה מיד לאחר commit. אחרי הפריסה רעננו את האפליקציה.

`kidsYoutubeVideos` שומר snapshot של האישורים, שמות הסרטונים והערוצים, מיפוי הקישורים ורשימת הסרטונים לפי ערוץ. `kidsYoutubeLastInstance` שומר את המופע האחרון שהצליח. שני הנתונים משויכים לנתיב האפליקציה כדי שלא להשתמש ברשימות של repository אחר באותו origin.

כאשר רשימת הקישורים העדכנית נטענה, המטמון נחתך לפיה **לפני** בקשות השמות והערוצים. ערוצים שהוסרו לא יחזרו מהמטמון. הגבלה חדשה של maxVideos חלה גם על נתונים שמורים. תשובה מוצלחת וריקה מערוץ מסירה סרטונים ישנים שלו. שורות עם קישור לא תקין אינן מאשרות תוכן. רשימה עדכנית שכולה קישורים לא תקינים מנקה את האישורים הישנים ומציגה הודעה לבדיקה של ההורה.

אם קובץ האישורים אינו נגיש בגלל ניתוק או תקלה ברשת, מוצגת הרשימה האחרונה הידועה עם הודעה מפורשת. שינויים חדשים של ההורה אינם יכולים להגיע למכשיר עד שחוזר חיבור תקין. לאחר חיבור מחדש מתבצע רענון. מחיקה במכשיר ההורה אינה יכולה לבטל מייד תוכן במכשיר מנותק.

ה־Service Worker שומר רק app shell ואייקונים, בשיטת network-first. הוא אינו שומר סרטונים או streams. **הצפייה עצמה דורשת אינטרנט.** כאשר localStorage חסום או מלא, האפליקציה ממשיכה להציג מידע זמין, אבל אינה מבטיחה שחזור בהפעלה הבאה.

## הנגן

לחיצה על כרטיס מאושר פותחת overlay שמכסה את המסך. כפתור ״← חזרה״ מרוקן את `iframe.src` לפני סגירת הנגן. כפתור Back של Android/הדפדפן ו־Escape סוגרים גם הם את הנגן. תוצאת בקשת נגן שהתבטלה אינה יכולה לפתוח אותו מחדש אחרי הסגירה.

לפני פתיחת embed נבדק מידע הסרטון דרך `/api/v1/videos/{id}`. כשל מעביר אוטומטית למופע הבא. ה־URL כולל:

```text
autoplay=1&related_videos=false&continue=0&comments=false&iv_load_policy=3
```

ה־sandbox מאפשר scripts, same-origin ו־presentation, ללא popups, forms או top-navigation. האפליקציה אינה מציגה חיפוש, שיתוף, המלצות, תגובות או קישורי YouTube.

הנגן הוא iframe ממקור אחר. טעינת iframe או תשובת metadata **אינן הוכחה שהסרטון מתנגן**. הדפדפן אינו מאפשר לאפליקציה לבדוק כל שגיאת stream פנימית; עבור תקלה כזאת יש כפתור ״נסו נגן אחר״ והודעה פשוטה. autoplay יכול להיחסם עד לחיצה בתוך הנגן. ביטול ההמלצות וההמשך האוטומטי תלוי במופע שמכבד את פרמטרי Invidious.

ה־sandbox חוסם יציאה לחלון העליון/חלונות קופצים, אך אינו אוסר ניווט פנימי בתוך ה־iframe. לכן הפרויקט מסנן את רשימת הבחירה ומקשיח את ה־embed, אך אינו יכול להבטיח חסימה מוחלטת של כל תוכן אחר בתוך נגן ציבורי שאינו בשליטתו. זהו גם אינו תחליף לנעילת הטאבלט: אפשר להשתמש בנעיצת מסך ובקוד של ההורה כדי לצמצם יציאה לאפליקציות אחרות.

אין קוד פרסומות באתר ואין fallback לנגן YouTube. זמינות הניגון ואופי התוכן של מופע ציבורי תלויים במפעילו ובגישה שלו ל־YouTube. לא הובטחה זמינות מתמדת.

## התקנה ב־Android

1. פתחו את כתובת GitHub Pages ב־Chrome עם חיבור לאינטרנט.
2. אם מופיע כפתור ״הוספה למסך הבית״ באפליקציה, לחצו עליו. אפשר גם להשתמש בתפריט Chrome → ״התקנת אפליקציה״ / ״הוספה למסך הבית״, לפי הגרסה.
3. פתחו את האייקון ממסך הבית. המניפסט מגדיר מצב standalone, כך שממשק הדפדפן הרגיל מוסתר.
4. בדקו סרטון שאישרתם, חזרה למסך הראשי ועדכון רשימה אחרי commit.

המניפסט כולל אייקונים בינאריים בגודלי 192 ו־512 עם משולש לבן בתחום הבטוח של maskable icon. אייקוני ההתקנה אינם דורשים יצירה נוספת.

## בדיקות וגבולות האימות

בדיקות הפיתוח משתמשות רק ב־Node.js ובמודולים מובנים. Node אינו נדרש להפעלה או לפריסה:

```bash
node --test tests/app.test.cjs
```

הדוגמאות לבדיקות נמצאות ב־`tests/fixtures/example-list.txt`, בנפרד מרשימת ההורה. אפשר לערוך את `videos.txt` ולהוסיף אישורים בלי לשנות את הבדיקות.

**47 מתוך 47 בדיקות עברו.** הבדיקות מריצות את JavaScript האמיתי מה־HTML בתוך DOM מדומה, עם תשובות API ומטמון מבוקרים. הן מכסות:

- syntax, קובץ הדוגמאות והכנסה בטוחה של שמות וכותרות כטקסט.
- רשימה פשוטה, הערות בתחילת שורה ובסופה, שורות ריקות ו־BOM/CRLF.
- זיהוי קישורי סרטונים וערוצים, כינויים, שמות אוטומטיים ו־resolveurl.
- דחיית קישורים לא תקינים, fallback של metadata ושמירת שמות בעת תקלה.
- הסרת קישורים מהמטמון וערוץ שהכינוי שלו נפתר למזהה חדש.
- אישור ידני וערוצים, דילוג על מזהים לא תקינים ומחיקה מהמטמון.
- pagination, continuation מקודד, מגבלת maxVideos, token שחוזר ו־100 עמודים.
- deduplication, טעינה במקביל, API לא תקין ו־authorId שאינו מתאים לערוץ.
- fallback בין מופעים, ערוץ שנכשל בלי לעצור אחר ועמודים שהתקבלו חלקית.
- localStorage fallback, עבודה ללא localStorage והפרדת נתיבי repositories.
- כפתור ״עוד סרטונים״ משתמש תמיד באישורים שבזיכרון; כשל כתיבה למטמון אינו מחזיר אישורים שבוטלו.
- נגן fullscreen כ־overlay, params, sandbox, סגירה וביטול בקשות.
- נתיבי manifest, מידות PNG, רישום Service Worker, install/activate ו־offline shell.
- נוכחות כללי RTL, grid לטאבלט, tap targets והפחתת תנועה.

**לא אומתו:** ניגון חי במופע ציבורי, CORS שלו מתוך GitHub Pages, תצוגה בדפדפן אמיתי או התקנה על טאבלט Android. בדיקות התצוגה כאן בודקות את הקוד והכללים, ולא צילום של הפריסה בפועל. נדרשת בדיקה במכשיר אחרי פרסום והוספת קישורים אמיתיים שאושרו.
