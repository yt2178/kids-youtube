# Kids YouTube — סרטונים לילדים

אפליקציה סטטית בעברית וב־RTL, המתארחת ב־GitHub Pages. ללא framework, backend, מסד נתונים, מפתח API, dependencies או build. הניגון נעשה באמצעות Invidious, בלי מעבר אוטומטי ל־YouTube שעלול להציג פרסומות.

## להורה: הוספה והסרה

1. בטלפון: YouTube → שיתוף → העתקת קישור לסרטון או לערוץ.
2. פתחו [את הרשימה לעריכה](https://github.com/yt2178/kids-youtube/edit/main/videos.txt).
3. הדביקו קישור בשורה חדשה ולחצו **Commit changes**.
4. אחרי שהפריסה ב־Actions הסתיימה, לחצו באתר על **רענון הסרטונים**. בדקו שהתמונה, השם והסרטון נכונים.

אין צורך לכתוב שם או מזהה: האתר מזהה את סוג הקישור ומביא שמות אוטומטית. אם ספק המידע אינו זמין, סרטון עם מזהה מפורש מופיע בינתיים כ״סרטון מאושר״; ערוץ עם כינוי שלא זוהה עדיין ממתין לזיהוי.

```text
// הערה להורה בלבד
https://youtu.be/VIDEO_ID_HERE // סרטון שבדקתי
https://www.youtube.com/@CHANNEL_HANDLE_HERE // כל הסרטונים הרגילים של הערוץ
```

החליפו מצייני מקום בקישורים אמיתיים. רווח ו־`//` מאפשרים הערה אחרי קישור; `//` בתחילת שורה מבטל את השורה. שורות ריקות אינן מאשרות תוכן. להסרה: מחקו את השורה או הפכו אותה להערה. הרשימה וההערות ציבוריות ב־GitHub. הרשימה הנוכחית של ההורה נשמרה במהלך השדרוג.

קישורי סרטונים: watch, youtu.be, shorts, live, embed, music. קישורי ערוצים: channel/UC, @handle, c/name, user/name. אתרים אחרים וקישורי playlists נדחים. אישור ערוץ מתיר גם תוכן עתידי שלו; ה־API שבו משתמשים מביא את לשונית הסרטונים הרגילים, ולא את לשוניות Shorts/Live. אפשר לאשר סרטוני Shorts/Live בנפרד; ניגון שידור חי אינו מובטח במקור MP4.

## שלושה מסכים

- **סרטונים שאבא אישר**: אישורים לסרטון בודד, למעט סרטונים שזוהו כשייכים לערוץ שכבר אושר.
- **ערוצים מאושרים**: שם, תמונה ומספר הסרטונים שכבר נטענו. לחיצה מציגה את סרטוני אותו ערוץ בלבד. המספר אינו סך כל הסרטונים שקיימים בערוץ.
- **כל הסרטונים**: איחוד שתי הקבוצות בלי כפילויות. זהו מסך הפתיחה, גם כאשר אושרו רק ערוצים.

יש חיפוש מקומי לפי שם הסרטון, היוצר והערוץ, עם השהיה של 150ms. הוא אינו מחפש ב־YouTube ואינו מוסיף אישורים. חיפוש מוצא רק סרטונים שכבר נטענו. מיון לפי הרשימה, החדשים קודם או שם; סינון לפי ערוץ מאושר. אם אין תאריך, הסרטון מופיע אחרי סרטונים עם תאריך במיון החדש ביותר. שאילתת החיפוש והגלילה נשמרות במעברים ובחזרה מהנגן.

ערוצים נטענים תחילה בעמוד אחד, במקביל עד שלושה ערוצים. **עוד סרטונים** מרחיב את הכרטיסים וטוען עמוד נוסף מכל ערוץ רלוונטי. התצוגה מוגבלת ל־60 כרטיסים נוספים בכל פעולה. יש מגבלות של 100 עמודים ו־5,000 סרטונים לערוץ, ובדיקת token שחוזר על עצמו. `maxVideos` נתמך גם בפורמט JSON הישן בתוך videos.txt.

## נגן ו־Fallback

הנגן פותח overlay ומנסה מדיה באמצעות `<video>` מקומי של הדפדפן, שמקבל אירועי `canplay`, `playing`, `error` ו־timeout. מקור MP4 משולב עשוי להיות חסר אצל ספק, גם כאשר הנגן הרשמי שלו מצליח באמצעות DASH. במקרה כזה עוברים אוטומטית לנגן התאימות הרשמי של אותו Invidious, לאחר בדיקת האישור: אישור ידני או שיוך עדכני לערוץ מאושר. אין בקשת metadata נוספת כתנאי ל־embed; כשל CORS של ה־API אינו מונע ניסיון נגן של סרטון שאושר כבר. המקור האחרון הזמין מקבל קדימות לזמן מוגבל.

נגן התאימות פועל בתוך `player.html` מקומי, עם `player.js` סטטי. רק הודעה מאומתת מהחלון ההורה יכולה להגדיר בו פעם אחת את הסרטון. האפליקציה מאפשרת iframe מקומי בלבד; המסך המקומי קובע CSP שמרשה את כתובת `/embed/VIDEO_ID` המדויקת של הספק הנבחר. ה־iframe החיצוני מקבל sandbox עם scripts/same-origin/presentation לצורכי JavaScript והעדפות הנגן; אין popups, forms או top navigation. מקור ספק זהה למקור האפליקציה נדחה. ההרשאות נקבעות באמצעות `allow`, בלי `allowfullscreen` כפול. פרמטרי הנגן מבטלים related videos, comments והמשך אוטומטי. אין fallback אוטומטי ל־YouTube.

כל פתיחה חדשה מבטלת את הבקשה הקודמת. לניסיון מדיה עד 6 שניות, בקשת metadata עד 4 שניות, תקציב 18.5 שניות לסבב ומספר ספקים מוגבל. כשל HTTP, metadata לא תקין, timeout או error שנגישים לאפליקציה גורמים למעבר אוטומטי. כפתור ״נסה שוב״ מנקה זמנית את כשלי שתי דרכי הניגון ואת כשל בקשת האימות של אותו סרטון, ומתחיל סבב אחד מוגבל. timeout של iframe מסמן cooldown; כשל frame מסמן את אותו סרטון בלבד, והפרת CSP שנגישה למסך הנגן מפעילה fallback. ״← חזרה״, Back ו־Escape עוצרים את המדיה/מרוקנים את iframe.src ורק אז מסתירים את הנגן.

**גבול חשוב:** iframe ממקור חיצוני לא מספק אירוע ניגון אמין לאפליקציה. אירוע load אינו מוכיח ניגון, ומסומן בבדיקה במפורש `loaded-not-playback-proof`. אם הנגן נטען אך מציג שגיאת stream פנימית, נדרש ״נסו נגן אחר״. אי אפשר להבטיח fallback אוטומטי לכל שגיאה פנימית ב־iframe באמצעות GitHub Pages בלבד. Sandbox מונע יציאה לחלון העליון. מדיניות הנתיב המדויק חוסמת ניווט רגיל לנתיבים אחרים של הספק, אך התאמת נתיבי CSP אינה נאכפת באותה צורה אחרי HTTP redirect, ואין לנו שליטה בתוכן שהספק מגיש בכתובת המותרת. הפרויקט אינו מחסום נגד גישה לכל תוכן שאינו מאושר מתוך ספק חיצוני/דפדפן בעל הרשאות. אין טענה שהמגבלה הזאת נפתרה באמצעות JavaScript.

## ספקים ו־CORS

רשימת `INVIDIOUS_INSTANCES` נמצאת במקום אחד בראש `app.js`; הפרמטרים נמצאים ב־`SETTINGS`. `providers.js` מרכז בקשות, timeouts, מיון ספקים, cache ושגיאות. API ומדיה מקבלים דירוג נפרד: חסימת JSON אינה מוכיחה שהמדיה מאותו ספק חסומה.

שגיאות 401/403/429 מקבלות cooldown מידי; 500 חוזר גורם ל־cooldown; 404/תגובה לא תואמת אינם פוסלים את כל הספק. נרשמים success/failure/time/response average/failure count/cooldown. cooldown מוגבל עד חמש דקות, מצב הספק נשמר לעשר דקות. בדיקת health מבוצעת פעם בשתי דקות ובחזרה לחלון, כשיש חיבור ואין ניגון/טעינה; היא בודקת ספק אחד ולא יוצרת סערת בקשות. הצלחת `/stats` אינה מוכיחה זמינות מדיה.

**המגבלה של GitHub Pages:** API נקרא ישירות מהדפדפן. אם ספק לא מאפשר CORS, JavaScript לא יכול לתקן זאת. לא נוספו no-cors hacks, proxy ציבורי או עקיפת אבטחה. דפדפן אינו מבדיל תמיד בין CORS ובין כשל רשת, ולכן הקוד מסווג אותם כ־NETWORK_OR_CORS. כשל מטופל, אך הדפדפן עדיין עשוי לרשום אותו ב־Console. אין הבטחה שכל הספקים הציבוריים יעבדו מכל רשת. המפעילים ו־YouTube יכולים לשנות זמינות בכל רגע.

רשימת מופעים רשמית: https://docs.invidious.io/instances/ . הופעה ברשימה אינה בדיקת CORS או ניגון.

## מטמון ועדכונים

| מידע | משך שמירה |
| --- | --- |
| מידע סרטון וזיהוי כינוי ערוץ | 6 שעות |
| שם ותמונת ערוץ | 12 שעות |
| עמוד סרטונים בערוץ | 5 דקות |
| מצב ספק | 10 דקות |
| thumbnails | 7 ימים, עד 200 תמונות |
| רשימת ערוץ אחרונה לצורכי תקלה | עד 7 ימים מהבקשה האחרונה שהצליחה |

Metadata מקומי מאומת למבנה/ID. בקשות זהות במקביל מתאחדות. תמונות משתמשות ב־lazy loading של הדפדפן, placeholder ברקע, reuse של nodes ושמירה מוגבלת ב־Service Worker. תמונות מאותו CDN נטענות רק בקרבת המסך; המרחק המדויק נבחר על ידי הדפדפן. הודעת הדפדפן על deferred lazy image events היא הודעת מידע תקינה.

`videos.txt` נקרא ב־`cache:'no-store'` ואינו נשמר או מיורט ב־Service Worker. הרשימה העדכנית נחתכת ומסירה אישורים שבוטלו לפני בקשות metadata. שינוי ברשימה ריקה מנקה אישורים; מידע שנשמר אינו מוסיף מחדש מקור שהוסר. App shell משתמש ב־network-first; מדיה אינה נשמרת, ולכן הצפייה דורשת אינטרנט.

אם הרשימה אינה נגישה, נעשה שימוש ברשימה האחרונה הידועה עם הודעה. מכשיר מנותק אינו יכול לדעת שהורה הסיר אישור עד שיחזור חיבור. localStorage אינו מחסום אבטחה נגד משתמש שיש לו גישה ל־DevTools או למכשיר. עבור סרטון שהגיע רק מרשימת ערוץ שמורה, הנגן דורש אימות עדכני של שיוכו לערוץ לפני ניגון; נתוני תצוגה שנשמרו אינם הוכחת אישור. ילדים אינם יכולים להוסיף URL מתוך האתר. נעיצת מסך וקוד הורה נדרשים אם רוצים למנוע יציאה לאפליקציות אחרות.

## פריסה והתקנה

הקבצים בשורש הריפו: index.html, app.js, providers.js, manifest.json, sw.js, videos.txt ושני אייקונים. הכול בנתיבים יחסיים, גם לאחר שינוי שם הריפו. `qa/mobile.html` הוא מסך בדיקת פריסה בלבד, אינו חלק מניווט הילדים.

GitHub Pages מוגדר ל־GitHub Actions. כל commit ל־main מריץ את הבדיקות ומפרסם רק אחרי הצלחה. אין npm install או build. ב־Android: Chrome → תפריט → התקנת אפליקציה/הוספה למסך הבית. בדיקת התקנה על Android אמיתי מצריכה מכשיר פיזי ואינה מוחלפת בבדיקת פריסה ברוחב טלפון.

## בדיקות

```bash
node --test tests/*.test.cjs
```

Node משמש לפיתוח/CI בלבד. tests/app.test.cjs מריץ את קוד האפליקציה האמיתי ב־DOM מבוקר, ו־tests/providers.test.cjs בודק את שכבת הספקים. הדוגמאות לבדיקה נמצאות ב־tests/fixtures/example-list.txt, כך שעריכת רשימת ההורה אינה שוברת את CI. תוצאות הבדיקה החיה והגבולות שלה מתועדים ב־AUDIT.md.

מצב בדיקה להורה: הוסיפו `?diagnostics=1` לכתובת האתר. הוא מציג נתוני health ובקשות מתוך הדפדפן וכפתור לניקוי מטמון metadata. המצב אינו משנה אישורים ואינו מאפשר להזין כתובת. לא נשלחת טלמטריה לשרת שלנו. זמני בקשות חיצוניות מסוימות אינם חושפים גדלי העברה בגלל מדיניות timing של הדפדפן.

אפשר לערוך במשותף בלי Google: ההורה השני צריך חשבון GitHub והרשאת collaborator לריפו. אין חיבור ל־Google Sheets ואין שמירה באמצעות חשבון Google מתוך האתר.

מקורות: https://docs.invidious.io/api/ , https://docs.invidious.io/api/channels_endpoint/ , https://docs.invidious.io/url-parameters/ .

בכתובת האתר עם `?diagnostics=1` מופיע מסך אבחון להורה. אפשר להשהות כל אחד מהמקורות הקיימים למשך חמש דקות במכשיר הנוכחי בלבד, או להפעילו מחדש. ההשהיה חלה גם על בדיקות בריאות ועל כפתור ניסיון חוזר; היא אינה משנה את רשימת האישורים או את ההגדרות במכשירים אחרים. שימוש בכפתור ״נסו נגן אחר״ מבטל העדפה שמורה למקור הקודם ומדלג עליו לזמן קצר עבור הסרטון המסוים.
