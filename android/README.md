כל הפרויקט נמצא בריפו **yt2178/kids-youtube**, והפרויקט של אפליקציית הילדים בתיקיית **android**.

1. בתיקיית הפרויקט הקיימת הריצו `git pull`.
2. ב־Android Studio בחרו **Open** ופתחו את `kids-youtube-full/android`.
3. המתינו ל־Gradle Sync. במידת הצורך התקינו Android SDK 36 וכלי בנייה 35.0.0.
4. בחרו **app**, חברו את המכשיר ולחצו ▶ Run.

לא צריך להתקין Node, framework, שרת, מסד נתונים או Gradle בנפרד. Gradle Wrapper הרשמי נמצא בריפו. בהורדה ובבנייה הראשונות נדרש אינטרנט כדי להביא את SDK והתלויות. האתר הסטטי עדיין אינו דורש build.

## מבנה

```text
kids-youtube/
├── android/
│   ├── settings.gradle
│   ├── build.gradle
│   ├── gradlew / gradlew.bat
│   ├── gradle/wrapper/
│   ├── prepare-assets.gradle
│   └── app/                 ← אפליקציית הילדים
├── index.html / app.js      ← מסך הילדים המשותף
├── icons/
├── parents.html            ← עמוד ההורים, ללא התקנה
└── videos.txt              ← קובץ תאימות היסטורי בלבד; אינו מקור ההרשאה הפעיל
```

מודול parent מהניסוי הקודם נשמר בקוד לצורכי נסיגה בלבד, אינו נפתח כברירת מחדל ואינו משנה את הרשאות Supabase הפעילות. למפתח בלבד: `-PincludeParentCompanion=true`.

נגן NewPipeExtractor/Media3 המקורי נשמר; נעשו התאמות UI לאזורי מערכת, מקלדת, טקסט מוגדל ומסכים נמוכים. הממשק כולל שלושה טאבים, חיפוש מקומי, thumbnails עצלים ועמודים. אין נגן YouTube חיצוני, שיתוף או רצף ניגון באפליקציית הילדים.

דורש **Android 6 ומעלה** ו־WebView מעודכן. התאמה לגדלי מסך אינה הבטחה לכל גרסת Android ישנה. אין יעד iOS בפרויקט.

## בנייה ובדיקות

```bash
cd android
./gradlew :app:testDebugUnitTest :app:assembleDebug
```

ב־Windows משתמשים ב־`gradlew.bat`. ה־APK נמצא ב־`app/build/outputs/apk/debug/app-debug.apk`.

CI בונה עם Wrapper את הפרויקט המוגדר כברירת מחדל, בודק שאריזת הממשק ב־Gradle זהה לאריזה שנבדקה ב־Node, ובודק גם את קוד ההורה הקודם. Node נדרש רק למפתח שמריץ את בדיקות האתר, לא לפתיחת הפרויקט ובנייתו ב־Studio.

הבנייה המקומית ב־Android Studio מתבצעת מול הקוד שהורדתם ב־Git. מספר ה־commit מוטמע בגרסת debug כאשר Git זמין. אין פרסום APK או ZIP אוטומטי ב־CI.

השיתוף/האישור בדפדפן, המקלדת, rotation וניגון בגרסה החדשה צריכים גם בדיקה במכשיר אמיתי. המשתמש דיווח שהנגן המקורי עובד במכשיר שלו; זו אינה בדיקה פיזית עצמאית שלנו.


## סיכום חקירת הרשאות ותקשורת — 10.10.2026

**כשל הנעילה — סגור ומוכח בבדיקות, PR #21.** התיקון מוזג ל־main ב־`3c5caa94cfd20c03a4d5ae138bf13edff2faf875`. העבודה המאומתת היתה הפרדה בין נעילת מצב האישורים לבין פעולות OkHttp החוסמות (כולל DNS/TCP/TLS וקריאת גוף), הפרדת נעילת האתחול של NewPipe, ודחיית תשובות הרשאה מיושנות שמגיעות במקביל. נבדקו concurrency/fail-closed עם MockWebServer והרצת Java/Android מלאה; ב־CI של ראש ה־PR `31452258b1750a59dc7932f534c8c2b6f3fc9f11` עברו גם 254 בדיקות Node ו־Mock ADB selection. אין לפתוח שוב את סעיף הנעילה ללא ראיה חדשה.

**עיכובי TCP/TLS — מקורם עדיין אינו ידוע.** התיקון לנעילה *אינו* הוכחה שהעיכובים ברשת נפתרו; אין ראיה מספקת לשייך אותם ל־DNS, ל־TLS, ל־Android/WebView, לשרת או לספק התקשורת. לא שונו TLS, IP family, pool החיבורים, פרוטוקול HTTP או timeouts כלליים רק כדי להשתיק שגיאות. לוגי `KidsNetwork` מאפשרים בבדיקה פיזית עתידית להבדיל בין המתנה לנעילה, DNS/TCP/TLS והמתנה לשרת.

### בדיקת המכשיר היחידה שעוד נדרשת — במועד שיתאפשר

אין צורך לאסוף עוד לוגים או לחזור על בדיקות CI כעת. בבדיקה העתידית מעדכנים תחילה את ה־checkout ל־`origin/main`, בונים ומתקינים **פעם אחת** ב־Android Studio על המכשיר הפיזי, ומוודאים שאין שינויים מקומיים ב־Java/Gradle המשנים את ה־build. מבצעים capture **אחד בלבד** מהשורש של הריפו, ב־PowerShell:

```powershell
.\scripts\collect-late-authorization.ps1 -Serial "J034XFCGCH01028100" -Seconds 180 -ExpectedBuildSha (git rev-parse HEAD) -OutputDir .\diagnostics
```

הסקריפט הקיים משתמש ב־`adb -s`, ולכן אינו מתבלבל בין אמולטור לטלפון הפיזי. הוא מבצע הפעלה אחת, מאמת שה־APK המותקן מדווח את ה־build SHA הצפוי, אוסף אירועי `KidsStartup/KidsNetwork/KidsCatalog/KidsWeb/KidsPlayback`, ומסמן `CAPTURE_COMPLETE` **רק** אם זוהו פתיחה אחת ולפחות שתי בדיקות הרשאה מחזוריות. אחרת `INCOMPLETE_EVIDENCE` ולא הצלחה. קובצי ה־summary וה־log המסוננים נכתבים ל־`diagnostics`; לוגים גולמיים זמניים נמחקים. אין ניקוי logcat, איפוס נתונים, הרשאות חדשות או שינוי רשת. זמן 180 שניות מתאים למחזור הבדיקה הנוכחי אך אינו מבטיח שני polls בכל מצב רקע/שינה.

**השאלה היחידה של הבדיקה:** האם הנעילה באמת אינה מעכבת את רצף האישורים במכשיר, ומהם זמני שלבי DNS/TCP/TLS ותגובת השרת כשמתרחשים עיכובים. עד לקבלת Logcat מה־APK המזוהה, אי אפשר לקבוע שסיבת עיכובי TCP/TLS נמצאה או נפתרה. גם במקרה של תוצאה חלקית אין להיחפז לשינויי רשת חדשים.
